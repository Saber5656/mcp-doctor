# Title

Markdown renderer

# Summary

Implement `src/report/render/markdown.ts`: GitHub-flavored Markdown rendering of the
report (summary table, findings table per client, probe table) suitable for pasting
into issues/PRs or writing via `--output`.

# Context

DESIGN.md §13 (markdown). Target consumer: humans sharing scan results in GitHub
issues and CI job summaries (`$GITHUB_STEP_SUMMARY`).

# Scope

- `src/report/render/markdown.ts`
- `tests/unit/report/markdown.test.ts` + golden fixtures

# Detailed Requirements

1. Structure:
   - `# mcp-medic report` + one-line mode/timestamp/version.
   - `## Summary` — table: errors / warnings / info / suppressed / servers / probed.
   - `## Findings` — one table per client with columns
     `Severity | Rule | Server | Problem | Fix | Location`; severity as text +
     emoji (❌/⚠️/ℹ️); Location as `file:line` in backticks. Grouping rules for
     findings: by `serverKey`'s client when present; else by the client of the
     `inventory.configFiles` entry matching `location.file`; else under a final
     `### General` table. Zero findings → `## Findings` contains the single line
     `No findings.` and no tables.
   - `## Probes` (when connect ran) — `Server | Status | Startup | Tools | Protocol`.
   - `## Notes` — bullet list of `report.inventory.visibilityNotes` (engine and
     orchestrator notes are already merged there by `assembleReport` — issue 31).
   - Footer line: `Generated by [mcp-medic](https://github.com/Saber5656/mcp-medic) v<version>`
     (static string; no URL fetches).
2. Escaping: pipe `|`, backtick, `<`, `>` in untrusted strings escaped for table
   safety **after** `sanitizeForTerminal` (reused — control-char stripping applies to
   markdown too); newline in cells → `<br>`.
3. Long values: cell content hard-capped at 120 chars with `…` (full detail remains
   in JSON format; note under the table when truncation occurred).
4. Deterministic; string-returning; no ANSI ever.

# Acceptance Criteria

- [ ] Golden fixtures: healthy, findings-mix, connect-mode.
- [ ] Adversarial fixture (pipes/backticks/ANSI/HTML in names & details) renders to
      valid GFM: tables keep column counts (assert row cell counts), no raw `<script>`
      (angle brackets escaped), no ESC bytes.
- [ ] Truncation note appears exactly when a cell was capped.

# Validation

`npm test -- --run tests/unit/report/markdown.test.ts`; reviewer pastes a golden file
into a GitHub comment preview to confirm rendering.

# Dependencies

31, 07 (`sanitizeForTerminal` used directly before markdown escaping).

# Non-goals

- No HTML report, no SARIF, no mermaid graphs.
